# 유전 알고리즘 최적화 기법들

이 디렉토리는 유전 알고리즘의 성능을 향상시키기 위한 다양한 최적화 기법들을 구현한 코드를 포함합니다.

## 수록된 최적화 기법

### 1. 캐싱(Caching)
- 같은 유전자 구성을 가진 개체의 적합도를 캐시하여 중복 계산 방지
- [캐싱 기법 세부 설명](./caching/readme.md)

### 2. 거친 인코딩(Coarse Encoding)
- 연속적인 유전자 값을 반올림하여 유사한 개체들을 동일하게 처리
- [거친 인코딩 기법 세부 설명](./coarse/readme.md)

### 3. 병렬 처리(Parallel Processing)
- 교차 및 돌연변이 연산을 병렬화하여 실행 시간 단축
- [병렬 처리 기법 세부 설명](./parallel/readme.md)

### 4. 스냅샷(Snapshot)
- 알고리즘의 현재 상태를 저장하고 복원하여 중단된 실행을 이어갈 수 있게 함
- [스냅샷 기법 세부 설명](./snapshot/readme.md)

## 최적화 기법 선택 가이드

- **계산 집약적인 적합도 함수**: 캐싱 기법 사용 권장
- **연속적인 값을 가진 문제**: 거친 인코딩 기법 사용 권장
- **대규모 인구와 복잡한 연산자**: 병렬 처리 기법 사용 권장
- **장시간 실행되는 알고리즘**: 스냅샷 기법 사용 권장

여러 기법들은 필요에 따라 조합하여 사용할 수 있으며, 문제의 특성에 맞게 적절히 선택해야 합니다.

## 원래 내용

*   **적합도 함수 계산 한 번만 수행 (Calculating fitness function once)**
    *   **적합도 함수의 계산은 가장 많은 자원을 소모하는 작업**입니다.
    *   따라서 빠른 유전 알고리즘은 각 개체에 대해 적합도 함수가 **한 번만 계산되도록 설계**되어야 합니다.
    *   예를 들어, 개체 객체를 초기화하는 동안 적합도 함수를 계산하고 그 결과를 속성으로 저장할 수 있습니다.
    *   소스에서는 이미 실용적인 예제에서 이 접근 방식을 사용하고 있다고 언급합니다.
    *   구현 예시에서 `Individual` 클래스의 `__init__` 메서드는 초기화 시 `gene_list`를 사용하여 `self.fitness = self.__class__.fitness_function(gene_list)`와 같이 적합도를 계산하여 `self.fitness` 속성에 저장합니다.

*   **적합도 함수 캐싱 (Fitness function caching)**
    *   유전 알고리즘의 진화 과정 중에 **같은 유전자 값을 가진 개체가 매우 자주 발생**할 수 있습니다.
    *   서로 다른 부모 쌍에서 같은 유전자 값을 가진 자손이 태어날 수 있고, 서로 다른 개체의 돌연변이 결과가 같은 유전자 값을 가진 개체로 이어질 수 있습니다.
    *   적합도 함수 계산이 가장 많은 자원을 소모하므로, 같은 유전자 집합을 가진 개체의 적합도 함수를 **두 번 계산하지 않는 것은 당연한 단계**입니다.
    *   계산 횟수를 줄이기 위해 **캐싱 메커니즘**을 사용할 수 있습니다.
    *   가장 간단한 캐싱 구현은 개체의 유전자 목록(`gene_list`)을 문자열 등으로 해시(`gene_hash`)하여 클래스 레벨의 캐시(`cache` 딕셔너리)에 저장하는 것입니다.
    *   개체가 생성될 때 (`__init__` 메서드 안에서), 유전자 해시가 캐시에 이미 있는지 확인하고,
        *   **캐시에 없으면** 적합도 함수를 계산하여 캐시에 저장하고 개체의 적합도 값으로 사용합니다.
        *   **캐시에 있으면** 저장된 적합도 값을 사용하고 캐시 히트 카운터를 증가시킵니다.
    *   예제 실행 결과에 따르면, 진화의 전체 기록에서 **약 3분의 1에 해당하는 개체가 같은 유전자**를 가졌습니다.
    *   이는 캐싱 덕분에 진화 과정에서 **3분의 2의 경우에만 적합도 함수를 계산했다는 것을 의미**하며, 이 사실이 유전 알고리즘의 작업 속도를 **크게 향상**시킬 수 있습니다.

*   **유전자 값의 거칠게 하기 (Coarsening values of genes)**
    *   **실수 유전자 인코딩**을 사용하는 문제에서 **매우 정확한 해를 찾을 필요가 없는 경우**가 많습니다. 예를 들어, 특정 조건을 만족하는 요트의 최적 길이를 찾을 때, 물리적으로 더 정밀하게 만들기 어렵기 때문에 센티미터 단위의 정확도로 설계하는 것이 현실적일 수 있습니다.
    *   유전자 값을 **거칠게 만드는 것** (예: 실수를 반올림하여 정수로 만들기)은 **같은 유전자 값을 가진 개체가 나타날 가능성을 자동으로 증가**시킵니다.
    *   이는 **적합도 함수 캐싱 적용을 훨씬 더 효과적으로** 만듭니다.
    *   구현 예시에서는 `__init__` 메서드에서 입력받은 `gene_list`의 각 유전자 값에 대해 `round(g)`를 사용하여 **반올림**합니다.
    *   개체의 실제 `gene_list` 속성은 이 **거칠게 만든 유전자 목록**으로 설정됩니다.
    *   캐싱을 위한 `gene_hash`는 이 **거칠게 만든 유전자 목록**을 기반으로 생성됩니다. 적합도 함수 계산 및 캐싱은 이 거칠게 만든 목록을 사용합니다.

*   **병렬 컴퓨팅 (Parallel computing)**
    *   유전 알고리즘의 가장 유용한 특징 중 하나는 **계산을 병렬화할 수 있는 능력**입니다.
    *   진화 과정은 교차(crossover)와 돌연변이(mutation)와 같이 **서로 관련이 없는 원자적(atomic) 작업들의 집합**으로 이루어집니다.
    *   이 특징 덕분에 진화 과정을 **여러 스레드, 프로세스, 또는 기계에 걸쳐 병렬화**할 수 있으며, 이는 진화 과정을 **크게 가속화**시킵니다.
    *   **교차 연산**은 각 부모 쌍을 **별도의 프로세스**에서 처리하여 병렬화할 수 있습니다.
    *   **돌연변이 연산**도 같은 방식으로 병렬화할 수 있습니다.
    *   **중요한 점은 교차 및 돌연변이뿐만 아니라 새로운 개체 생성, 즉 적합도 함수 계산도 병렬화된다는 것**입니다. 이것이 바로 진화 과정을 가속화하는 핵심입니다.
    *   구현 예시에서는 `multiprocessing.pool.Pool`을 사용하여 병렬 처리를 구현합니다. `crossover_operation` 및 `mutation_operation` 함수 내에서 `pool.apply_async`를 사용하여 각 교차 또는 돌연변이 작업을 풀(pool)에 제출하고, 작업 완료 후 결과를 모읍니다.
    *   테스트 결과에 따르면, 병렬화된 유전 알고리즘 버전이 단일 스레드 버전에 비해 **적어도 두 배 이상 빠르다**고 언급됩니다. (예시: 병렬 20분 13초 vs 단일 47분 55초).
    *   실제 속도 증가는 장치의 특성에 따라 다르며, **두 개 이상의 CPU가 있는 경우에만 가속화**가 가능합니다.
    *   이 동일한 접근 방식은 여러 기계에 걸쳐 계산 프로세스를 병렬화하는 데 사용할 수 있습니다 (수평 확장, horizontal scaling). 이것은 해를 찾는 과정을 **극적으로 가속화**할 수 있습니다.
    *   유전 알고리즘이 진화 프로세스를 확장할 수 있는 능력은 단일 스레드 모드로 실행될 수밖에 없는 다른 방법들과 달리 이 해 탐색 방법의 **주목할 만한 특징**입니다.

*   **개체군 스냅샷 (Population snapshot)**
    *   유전 알고리즘 실행 시간이 길게 예상되는 문제(예: 약 일주일)의 경우, 시스템 재부팅과 같은 예기치 않은 상황으로 인해 실행이 중단될 수 있습니다.
    *   이러한 경우, 처음부터 다시 시작하는 대신 **알고리즘이 중단된 지점부터 작업을 계속할 수 있는 방법**이 이상적입니다. 장시간 실행되는 운영 체제에서 예기치 않은 상황이 발생할 확률은 비교적 높습니다.
    *   개체군 스냅샷 방법은 한 세대의 **개체군을 어떤 저장소에 저장**하고, 필요할 때 **마지막 개체군을 복원하여** 진화를 계속할 수 있게 합니다.
    *   개체군 스냅샷을 저장하는 과정 자체는 시간이 걸릴 수 있으므로, **모든 세대를 저장하기보다는 주기적으로** (예: 10번째, 20번째, 50번째 세대마다) 스냅샷을 찍는 것이 좋습니다.
    *   이 접근 방식이 성능 향상 장에 포함된 이유는, **빅 데이터 문제**에서 예기치 않은 상황으로 인해 알고리즘 실행이 자주 중단되기 때문에, 특정 **체크포인트에서 실행을 복원하는 능력 자체가 해를 찾는 과정을 극적으로 가속화**하기 때문입니다.
    *   구현 예시에서는 개체군 `population`의 각 개체에서 `gene_list`를 추출하여 리스트로 만들고, 이 유전자 목록 리스트를 JSON 파일로 덤프(dump)하는 함수 (`dump_population`)를 보여줍니다.
    *   복원 함수 (`restore_population`)는 JSON 파일을 로드하고, 각 유전자 목록으로 새로운 `Individual` 객체를 생성하여 개체군 리스트를 구성합니다.

소스에서는 이러한 방법들 외에 **적합도 함수 계산 자체를 최적화**하는 것이 중요한 가속 방법이지만, 이는 특정 작업에 따라 분석이 달라지므로 일반적인 메커니즘을 제공하기 어렵다고 언급합니다. 유전 알고리즘 구현이 이러한 가속 방법 없이도 허용 가능한 결과를 보여줄 수 있지만, **최적화를 시도해야 하는 이유는 빠른 유전 알고리즘의 경우 같은 작업 시간 내에 더 철저한 탐색 (예: 더 큰 개체군 사용)을 할 수 있기 때문**이며, 개체군 증가는 더 나은 해를 찾을 가능성을 높입니다.
